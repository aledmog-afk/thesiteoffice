numlint.

A linter for the arithmetic inside prose.

Spell-checkers read your words. Nothing reads your numbers. numlint parses every quantity in a document — 8.5 km, £4.2m, two-thirds, 22.7 pct — works out how they relate, and tells you which ones cannot all be true at once. It checks the document against itself, so it needs no data, no network and no model. Everything below runs in this tab.

How it decides

Every number in a document is really a claim about an interval. Writing 8.5 km asserts a true value somewhere in 8.45–8.55; writing about 5 million asserts something much vaguer. numlint reads that precision off the page — decimal places, scale words, hedges like roughly or more than — and only reports a problem when the interval a number states cannot overlap the interval its neighbours imply. That is why it stays quiet about rounding, and why the things it does flag are arithmetic that cannot be right as written.

It never guesses

No model, no lookup, no heuristic scoring. A finding is a proof that two figures on the page contradict each other, and every one comes with the working.

Quiet by design

Across 5,302 documents of real newswire and general prose — 90,000 quantities — it raised two findings. Both were genuine errors in the source.

Built for drafts

CLI, library, SARIF for CI, and an MCP server so a model can check its own numbers before handing you the document.
